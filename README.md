# Course LMS API Backend

Серверная часть (API) для системы управления обучением (Learning Management System), разработанная на **Django REST Framework (DRF)**.

## 🛠 Стек технологий
* **Язык программирования:** Python 3.13
* **Фреймворк:** Django 6.x / Django REST Framework (DRF)
* **База данных:** PostgreSQL (pgAdmin 4) (Docker)
* **Асинхронные задачи и очереди:** Celery 5.x (Docker)
* **Брокер сообщений / In-memory БД:** Redis (Docker)
* **Интеграция сторонних API:** Stripe API (Платежная система)
* **Управление зависимостями:** Poetry
* **Качество кода:** Ruff (линтер и форматтер)

## 🚀 Развертывание проекта через Docker

Для работы приложения вам понадобится установленный [Docker Desktop](https://docker.com).

### 1. Настройка переменных окружения (`.env`)
Создайте файл `.env` в корне проекта и заполнить его по шаблону `.env.sample`.
> ⚠️ **Важно:** Для работы внутри Docker-сети в качестве хостов укажите имена соответствующих сервисов:
> `DB_HOST=db`
> `CELERY_BROKER_URL=redis://redis:6379/0`

### 2. Сборка и запуск контейнеров
Запустите сборку образов и поднятие всех сервисов (Django, PostgreSQL, Redis, Celery) одной командой:
```bash
docker compose up --build
```
*После успешного запуска API будет доступно по адресу: http://localhost:8000/*

### 3. Применение миграций и создание суперпользователя
Так как база данных инициализируется в изолированном контейнере, при первом запуске выполните команды миграции внутри контейнера `app`:
```bash
# Применить миграции
docker compose exec app  python manage.py migrate

# Создать администратора для доступа в админ-панель
docker compose exec app  python manage.py createsuperuser
```

### 4. 🧪 Запуск тестов
Вы можете запустить встроенные тесты приложения прямо внутри контейнера одной командой:
```bash
docker compose exec app python manage.py test
```

### 5. Полезные команды
* **Остановка проекта:** `docker compose down`
* **Просмотр логов конкретного сервиса (например, Celery):** `docker compose logs celery_worker -f`
* **Очистка неиспользуемых образов:** `docker image prune`


## 🚀 Локальное развертывание проекта без Docker

### 1. Клонирование репозитория
Склонируйте проект с GitHub и перейдите в корневую директорию:
```bash
git clone https://github.com/IrinaBatova/course-7-lms-api-backend.git
cd course-7-lms-api-backend
```

### 2. Установка зависимостей
Проект использует менеджер пакетов `Poetry`. Чтобы установить все зависимости, включая инструменты разработки (Ruff), выполните:
```bash
poetry install
```

### 3. Настройка переменных окружения (`.env`)
Создайте локальный файл `.env` в корне проекта:
```bash
cp .env.sample .env
```
Откройте созданный файл `.env` и заполните ваши секретные ключи и настройки подключения к PostgreSQL (название базы данных рекомендуется использовать `lms_apibackend_db`).

### 4. Подготовка базы данных
Перед запуском убедитесь, что в pgAdmin 4 создана пустая база данных, соответствующая названию в `.env`. Примените встроенные миграции:
```bash
poetry run python manage.py migrate
```

Создайте учётную запись администратора для доступа в админ-панель:
```bash
poetry run python manage.py createsuperuser
```

### 5. Запуск сервера разработки
```bash
poetry run python manage.py runserver
```
После запуска проект будет доступен локально по адресу: [http://127.0.0](http://127.0.0)

## 🧹 Проверка качества кода (Ruff)

В проекте настроен инструмент **Ruff**, заменяющий Flake8 и Black. 

- Для автоматического форматирования кода выполните:
  ```bash
  poetry run ruff format .
  ```
- Для проверки кода на ошибки и автоматического исправления мелких багов (и сортировки импортов):
  ```bash
  poetry run ruff check . --fix
  ```
